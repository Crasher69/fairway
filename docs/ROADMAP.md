# Порядок работ

Каждый этап заканчивается чем-то запускаемым.

## 1. Форвардинг (ядро)
- [ ] `internal/forward`: приём `CONNECT`, туннель через `io.Copy`
- [ ] обычный HTTP-форвардинг по заголовку `Host`
- [ ] диалер через апстрим-прокси: http/https CONNECT, socks5
- [ ] замер: connect time, TTFB, bytes/sec — уже на этом этапе
Проверка: браузер с прокси `127.0.0.1:8080` открывает сайты через апстрим.

## 2. Конфиг и пулы
- [ ] `internal/config`: JSON — proxies, lists, domains; валидация; hot-reload
- [ ] `internal/proxypool`: реестр, привязка домен → лист, семафор `max_parallel`
- [ ] выбор прокси: сначала round-robin (заглушка под будущий рейтинг)

## 3. Рейтинг
- [ ] EWMA по (домен, прокси): connect, TTFB, throughput, error rate
- [ ] скоринг + epsilon-greedy (позже — Thompson sampling)
- [ ] бан-детект: 403/429/капча → исключение из ротации для домена на N минут
- [ ] снапшот рейтингов на диск + загрузка при старте

## 4. MITM
- [ ] `internal/mitmca`: генерация корневого CA, экспорт `.crt`
- [ ] выпуск сертов на лету + кэш (LRU по домену)
- [ ] TLS-терминация на `CONNECT`, разбор HTTP, проброс к цели
- [ ] per-domain переключатель: расшифровывать / прозрачный туннель
- [ ] точный бан-детект по реальному HTTP-статусу

## 5. Админка
- [ ] `internal/stats`: кольцевые буферы, агрегация
- [ ] REST: proxies / lists / domains / stats
- [ ] SSE-стрим состояния
- [ ] фронт: таблица прокси домена, живой лог, графики (uPlot)
- [ ] авторизация токеном, bind только на 127.0.0.1

## 6. Прод
- [ ] кросс-сборка linux/amd64, Dockerfile на `scratch`
- [ ] нагрузочный тест: цель — держать несколько тысяч конкурентных туннелей
