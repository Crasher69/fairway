# Порядок работ

Каждый этап заканчивается чем-то запускаемым.

## 1. Форвардинг (ядро)
- [x] `internal/forward`: приём `CONNECT`, туннель через `io.Copy`
- [x] обычный HTTP-форвардинг по заголовку `Host`
- [x] диалер через апстрим-прокси: http/https CONNECT, socks5
- [x] замер: connect time, TTFB, bytes/sec — уже на этом этапе
Проверка: браузер с прокси `127.0.0.1:8080` открывает сайты через апстрим.

## 2. Конфиг и пулы
- [x] `internal/config`: JSON — proxies, lists, domains; валидация; hot-reload
- [x] `internal/proxypool`: реестр, привязка домен → лист, лимиты параллелизма
- [x] выбор прокси: round-robin за интерфейсом `Selector` (заглушка под рейтинг)

## 3. Рейтинг
- [x] EWMA по (домен, прокси): connect, TTFB, throughput, error rate
- [x] скоринг по цене + разведка + взвешенная лотерея (Thompson sampling — позже)
- [x] бан-детект: 403/429/451/407 и серия ошибок (капча — после MITM)
- [x] снапшот рейтингов на диск + загрузка при старте

## 4. MITM
- [x] `internal/mitmca`: генерация корневого CA, экспорт `.crt` (-export-ca)
- [x] выпуск сертов на лету + LRU-кэш по домену
- [x] TLS-терминация на `CONNECT`, разбор HTTP, проброс к цели
- [x] per-domain переключатель: расшифровывать / прозрачный туннель
- [x] настоящий HTTP-статус по HTTPS (капча по телу — ещё нет)

## 5. Админка
- [x] `internal/stats`: кольцевой буфер событий + подписка
- [x] REST: overview / domains / domains-{domain} / proxies / events
- [x] SSE-стрим событий с фильтром по домену
- [x] фронт: таблица прокси, живой лог, график TTFB (свой SVG, без зависимостей)
- [x] авторизация токеном, bind на 127.0.0.1, предупреждение при выходе наружу

## 6. Прод
- [x] кросс-сборка (build.sh: linux amd64/arm64, windows, macOS) и Dockerfile на scratch
- [x] нагрузочный тест (cmd/loadgen, docs/BENCHMARK.md): 1000 туннелей, 36 тысяч запросов в секунду

## Известные хвосты после этапа 1

- ~~**Throughput на мелких ответах шумит.**~~ Закрыто на этапе 3: скорость
  считается только по ответам от 32 КБ.
- **Нет keep-alive к апстриму.** Пока на каждый HTTP-запрос новое соединение
  (`Connection: close`). Пул соединений — этап 2, вместе с семафорами.
- **`go test -race` на этой машине не запускается** — гонки требуют cgo, а gcc
  не установлен. Проверять гонки на Linux-сборке или поставить mingw.

## Известные хвосты после этапа 3

- ~~**Рейтинги не вытесняются.**~~ Закрыто на этапе 8: пара, не получавшая
  запросов сутки (`rating.DefaultEvictAfter`), забывается при автосохранении;
  действующие баны доживают до срока.
- **Капча не детектируется.** Сайт может отвечать 200 и отдавать страницу
  проверки — для распознавания нужно видеть тело, то есть этап 4.
- **Thompson sampling не сделан.** Сейчас epsilon-greedy: проще, предсказуемее
  и его видно в логе. Возвращаться к этому есть смысл, только если на боевых
  данных разведка окажется слишком дорогой.
- ~~**Порог `minSamples = 3` не учитывает возраст.**~~ Частично закрыто
  вытеснением: пара, простоявшая сутки, забывается целиком и проверяется
  заново, как новая. Внутри суток старые замеры по-прежнему считаются.

## Известные хвосты после этапа 4

- **Капча по телу ответа не разбирается.** Статусы теперь видны, но сайт может
  отвечать 200 и отдавать страницу проверки. Нужен разбор тела по признакам
  (характерные заголовки, размер, маркеры в HTML) — и обязательно с ограничением
  на объём, который мы готовы прочитать в память.
- **HTTP/2 к цели не поддерживается.** ALPN зафиксирован на http/1.1 с обеих
  сторон. Для скорости на многих мелких запросах h2 к цели дал бы выигрыш, но
  это отдельный разбор фреймов.
- ~~**Тело запроса не переигрывается.**~~ Закрыто на этапе 9: тело до 1 МиБ
  (`-replay-body`) буферизуется, и запрос повторяется на новом соединении,
  если от цели не пришло ни байта. Тело больше лимита уходит потоком без
  повтора.
- **WebSocket через MITM не проверялся.** Upgrade вычищается как hop-by-hop
  заголовок, то есть внутри расшифрованного туннеля ws сейчас сломается.
  Для таких доменов ставить `mitm: false`.

## Известные хвосты после этапа 5

- **Гранулярность таймера на Windows.** Два подряд `time.Now()` возвращают
  одно значение, поэтому подключения быстрее шага таймера измеряются как 0.
  Проверено зондом: 14 из 20 подключений к loopback дали ровно 0 мкс. На
  боевых прокси (десятки и сотни мс) это неважно, но локальные стенды
  показывают заниженный connect. Если понадобится точность — измерять пачками
  и делить, а не по одному замеру.
- **История только в памяти.** Кольцо на 5000 событий, при перезапуске
  теряется, а на большом трафике «последние минуты» превращаются в
  «последние секунды». Для долгой истории нужен отдельный слой.
- ~~**Админка только читает.**~~ Закрыто на этапах 7–8: правка конфига,
  снятие бана, массовые действия.
- ~~**Вид панели не проверен в браузере.**~~ На этапе 8 панель проверена
  в Chrome в обеих темах, на всех вкладках и на пустом экземпляре.

## Известные хвосты после этапов 6–7

- **Нет пула соединений к апстриму для обычного HTTP.** Главный ограничитель
  производительности: 2500 запросов в секунду против 36 000 у туннелей.
  Подробности в `docs/BENCHMARK.md`.
- **Нагрузка мерялась только на Windows** и только на одной машине.
  «Несколько тысяч туннелей» на Linux не проверено.
- ~~**Правка конфига и сторож файла работают параллельно.**~~ Закрыто:
  `Editor` после записи вызывает `Watcher.MarkApplied`, и сторож считает эту
  версию уже применённой. Окно между записью и меткой — миллисекунды против
  двухсекундного опроса; если сторож всё же успеет, конфиг применится дважды,
  что безвредно.
- ~~**Лицензия не выбрана.**~~ Выбрана Apache-2.0: файлы `LICENSE` и
  `NOTICE` в корне.

## Известные хвосты после этапа 8

- **Иконка только у Windows-сборки.** Для macOS нужен `.app`-бандл с `.icns`,
  для Linux — `.desktop` и PNG в `hicolor`; у консольного бинарника без
  бандла иконки там не бывает. `brand.PNG` умеет отдать растр любого
  размера, когда до этого дойдёт.
- **Нет VERSIONINFO в exe.** В свойствах файла не видно версии и описания:
  версия проставляется через `-ldflags` при сборке, а ресурс собирается
  заранее, и они разошлись бы. Можно генерировать ресурс в `build.sh`
  с той же версией.
- **Массовый выбор не переживает поиск.** Отметки хранятся по именам и
  остаются при смене фильтра (это удобно), но «отметить все» отмечает только
  показанные — так задумано, чтобы не удалить полсотни прокси одним
  случайным кликом.
